# Changelog

All notable changes to this project are documented here. The format follows
[Keep a Changelog](https://keepachangelog.com/en/1.1.0/) and the project uses
[Semantic Versioning](https://semver.org/).

From 2.0.0 onwards the three `@nestjs-automapper/*` packages are versioned
together: they share one IR, so a consumer cannot half-upgrade. Each package
also carries its own `CHANGELOG.md`, generated by Changesets.

## [2.0.0] — 2026-09-10

A ground-up rebuild. 2.0 ships under a new npm scope and **supersedes
`custom-automapper`**. It is not source-compatible with 1.x. Upgrade steps are
in [`docs/MIGRATION.md`](docs/MIGRATION.md).

| Package | Role |
|---|---|
| `@nestjs-automapper/core` | Mapping engine. Zero runtime dependencies. |
| `@nestjs-automapper/typeorm` | TypeORM schema adapter. |
| `@nestjs-automapper/nestjs` | Module, DI, response interceptor, request-body pipe, `automapper` CLI. |

### Highlights

- **The mapper reads your schema.** DTOs are derived from the entity with
  `Pick(User, [...])`, not restated. You don't need decorators or a
  TypeScript transformer plugin.
- **Broken mappings fail at boot.** `AutomapperModule` seals every mapping when
  the app starts. An unresolved field, an unknown dependency path, or a
  database-owned field in a write DTO stops `nest start`, naming the field, the
  source and a did-you-mean. `npx automapper check` gives CI the same guarantee.
- **The DTO decides the `SELECT`.** `mapper.nativeProjectionFor(Dto)` returns
  TypeORM find options that fetch only the columns the DTO uses. Computed fields
  project their declared sources, and relations the DTO never touches are not
  joined.
- **Mass-assignment protection from the schema.** A request body carrying `id`,
  `createdAt`, or any unknown key is rejected with a 400 that lists what was
  refused and what is accepted.
- **OpenAPI without `@ApiProperty`.** `mapper.schemaOf(Dto)` generates the
  schema, including computed fields, in OpenAPI 3.0 or 3.1.
- **Compiled mappings.** Each mapping compiles to one specialised function at
  seal. There is no reflection on the hot path, and the codegen is
  injection-safe.

### Added

#### `@nestjs-automapper/core`

- DTO builders: `Pick`, `extend`, and `Write`. Each returns a real runtime
  class whose constructor assigns every declared key.
- Resolvers: `auto`, `from`, `compute`, `resolve` (async), `constant`,
  `ignore`, `defaultTo`, `visible` (context-gated), `nested`, `collection`.
- `Mapper` with a declare → seal → serve lifecycle: `use`, `register`, `seal`,
  `map`, `mapArray`, `mapAsync`, `mapArrayAsync`, `mapInput`.
- Projection: `projectionFor` (neutral field selection) and
  `nativeProjectionFor` (the adapter's ORM-native options). A context-gated
  plan requires a context instead of over-fetching.
- Write path: `Write` DTOs are checked against the schema's write policy (primary,
  generated, create/update/delete date, version and discriminator columns).
  `reverseOf(Dto)` reports which fields are writable and why the rest are refused.
- `schemaOf(Dto, { version: '3.0' | '3.1' })`: OpenAPI schema generation.
- Object graphs: nested DTOs register themselves at seal. Cycles terminate, and
  shared references map once through a per-operation identity map.
- Type converters: `new Mapper({ convert: { date: v => … } })` applies one rule
  to every field of a declared type.
- `defineSchema()` schema tokens for sources with no runtime class: Prisma
  models, Drizzle schemas, plain interfaces. They get projection, OpenAPI and
  the write policy, not just mapping.
- `AutomapperError` with 12 structured error codes, each rendered with what
  failed, why, and what to do.
- Compile-time guarantees: dependency paths are typed, so a typo is a compile
  error. Unpicked fields are absent from the DTO type. Calling `map()` on an
  async DTO is a type error.
- `SchemaAdapter` port for writing adapters for other ORMs.

#### `@nestjs-automapper/typeorm`

- `typeorm(dataSource)` adapter. It reads column, relation, nullability, enum
  and provenance metadata from TypeORM, and needs no mapping decorators.
- Projection to `{ select, relations }`. The primary key is always included so
  TypeORM can hydrate relations.
- Lazy relations make the plan async, and their promises are awaited.

#### `@nestjs-automapper/nestjs`

- `AutomapperModule.forRoot` and `forRootAsync` (`useFactory`, `useClass`,
  `useExisting`). The mapper is sealed at boot, and a failed seal fails
  the bootstrap.
- `@InjectMapper(name?)` and `getMapperToken(name?)` for named mappers.
- `@MapTo(Dto)` with a global `MapToInterceptor`, which maps a handler's return
  value (object or array).
- Global `MapBodyPipe`. Plain `@Body() dto: CreateUserDto` is mapped and
  checked when the type is a `Write` DTO.
- `automapper check <compiled-module> [ExportName]` CLI for CI.

### Changed — breaking, relative to 1.x

- **Package names.** `custom-automapper` is replaced by `@nestjs-automapper/core`,
  `@nestjs-automapper/typeorm` and `@nestjs-automapper/nestjs`.
- **Runtime requirements.** Node.js ≥ 22.13 (was ≥ 16). NestJS ^12 (was
  ^10 or ^11). TypeORM ^1.1.1, reflect-metadata ^0.2.2, rxjs ^7.8.
- **Module format.** Dual ESM and CommonJS with explicit `exports` maps.
- **Nothing is mapped implicitly.** Every DTO field comes from `Pick` or from
  an explicit resolver.
- **Mapping requires a sealed mapper.** `map()` before `seal()` throws, and so
  does `register()` after it. `AutomapperModule` seals for you.

### Removed

The whole 1.x API. [`docs/MIGRATION.md`](docs/MIGRATION.md) maps each item to
its replacement.

- `createMap`, `createReverseMap`, `MappingProfile`, `MappingBuilder`,
  `MappingConfigurator`, `createMappingContext`.
- Decorators: `@AutoMap`, `@MapProperty`, `@MapNested`, `@Transform`,
  `@Ignore`, `@Default`, `@DateFormat`, `@Validate`, `@Mappable`, `@MapProfile`.
- Result caching (`cache` options, `setCacheEnabled`). Mappings are compiled
  once at seal, so there is nothing left to cache.
- Validation (`addValidation`, `validate`, `validateProperty`). Validate values
  with `class-validator`, `zod`, or a Nest `ValidationPipe`.
- `mapConditional`, `mapWithMetadata`, `clear`, `getMappings`.
- Strategies (`ArrayMappingStrategy`, `EnumMappingStrategy`,
  `PolymorphicMappingStrategy`) and utilities (`deepClone`,
  `getPropertyByPath`, `setPropertyByPath`, `convertNamingConvention`, …).
- NestJS: `AutoMapInterceptor`, `AutoMapPipe`, `@MapBody`, `@MapQuery`,
  `@UseMapper`, `@MapFrom`.

### Not supported, by design

These features from `@automapper/*` are left out on purpose. The reasoning is
in [`docs/ECOSYSTEM.md`](docs/ECOSYSTEM.md).

- `beforeMap` / `afterMap`: you can do the same in one line either side of the call.
- `constructUsing`: DTO constructors are generated and must assign every key.
- Auto-mapping entity getters (`isGetterOnly`). A getter's source columns
  cannot be projected. Use `compute()` with declared dependencies instead.
- Global naming conventions: column naming belongs to the adapter.
- A configurable error handler: a diagnostic you can switch off is one that
  gets switched off.

### Fixed

- The 1.x decorator pipeline never ran. Metadata was written to
  `prototype + propertyKey` and read from the constructor, so decorator-driven
  mapping produced `{}`. 2.0 is a rebuild, not a patch.

### Security

- Generated mapping code emits property keys only through `JSON.stringify` and
  passes resolvers as closures. A hostile column name cannot inject code.
- Write DTOs and `MapBodyPipe` reject database-owned and unknown fields at the
  request boundary.

## 1.x — `custom-automapper` (deprecated)

Versions 1.0.4 to 1.0.11 were published from the original codebase, which is
kept on the [`v1-archive`](https://github.com/nishit-shivdasani/custom-nestjs-automapper/tree/v1-archive)
branch. 1.x receives no further releases. Move to 2.0 using
[`docs/MIGRATION.md`](docs/MIGRATION.md).
