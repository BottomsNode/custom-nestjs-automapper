- (constraint) TypeScript 7.0 is a native Go port that ships NO compiler API. Consumers of that API break: nest build, the @nestjs/swagger and GraphQL CLI plugins, ts-jest, ts-loader, and type-aware ESLint. TS 6.0.3 is the last line with the API. Therefore build/emit on 6.x; TS 7 is a type-check target only.
- (decision) COMPETITIVE CONSEQUENCE of the TS7 finding: @automapper/classes requires a ts transformer plugin, which is a compiler-API consumer and therefore cannot run under TS 7. Our design requires no transformer plugin at all, so it works natively where the incumbent structurally cannot. This was not a known differentiator at spec time and materially strengthens CAP-1.

Fold all three into the adapter and the reverse-map drop rules.
- (decision) PARADIGM: compiler pipeline - front-ends (schema adapters) normalise to TypeDescriptor, a planner lowers that to a single IR (MappingPlan), and multiple back-ends (codegen, projector, explainer, validator, schema emitter) consume only the IR. Ports-and-adapters governs the schema boundary. Naming it a compiler loads the whole model for free: one IR, no back-edges, back-ends never talk to front-ends.
- (decision) AD-1 one-way dataflow. Binds all. Prevents an emitter reading adapter metadata directly, which would create a second source of truth about what a mapping does. Rule: adapters produce TypeDescriptor only; the planner is the sole consumer of descriptors; back-ends consume MappingPlan only and must not import an adapter or descriptor type.
- (decision) AD-2 MappingPlan node set is closed. Binds CAP-3,4,5,6,7,8,9. Prevents back-ends diverging on node semantics or one understanding a kind another ignores. Rule: ResolutionNode is a closed discriminated union on kind; every back-end switches exhaustively with a never-check and no default arm; adding a kind is a breaking core change that must update all back-ends in the same commit.
- (decision) AD-3 codegen never interpolates untrusted strings as code. Binds codegen, CAP-1, CAP-5. Prevents syntax breakage and code injection from column and field names that originate in ORM metadata or user config. Rule: property access is emitted as bracket notation with JSON.stringify-ed keys; all identifiers in generated source come from a fixed emitter-controlled alphabet; resolver functions are passed as closure arguments and never stringified into the body.
- (decision) AD-4 registry keys are class identity, never class name. Binds all. Prevents the v1 defect where keys built from class.name collided under minification and across modules. Rule: registry and compiled-function caches key on the constructor reference via Map/WeakMap; .name appears only in rendered error text.
- (decision) AD-5 single error taxonomy. Binds CAP-3, CAP-4. Prevents each package inventing its own error shape and fragmenting the CAP-4 promise. Rule: all errors extend AutomapperError in core with a machine-readable code and structured fields (sourceType, destType, field, candidates, adapter); message rendering is a core function, never per-package string building; adapters never throw raw Error.
- (decision) AD-6 dependency direction. Binds all packages. Prevents adapter-to-adapter coupling and core reaching into an ORM. Rule: core imports nothing; typeorm and nestjs import core only; no adapter imports another adapter; nestjs must not import typeorm. Enforced by lint rule plus pnpm strict resolution.
- (decision) AD-7 all mutable state is operation-scoped. Binds CAP-7. Prevents cross-request leakage and the v1 staleness defect. Rule: the only long-lived state is the registry and compiled functions, both keyed by type and immutable after registration; per-map state (identity map, ancestor chain, resolver memo) lives on a context created per top-level call and discarded on return; no module-level mutable state.
- (decision) AD-8 failure moves left. Binds CAP-3, CAP-4, CAP-10. Prevents divergent choices about where a rule is enforced. Rule: enforcement ladder is type system, then registration/boot, then first call, never at request time; a rule enforceable by types must not ship as a runtime check only.
- (decision) AD-9 async is a plan property computed once. Binds CAP-2. Prevents back-ends disagreeing on sync versus async and prevents floating promises. Rule: isAsync is the disjunction over plan nodes, computed during plan build and immutable; codegen emits either a sync or an async function for a pair, never both; the sync entry point is type-rejected for an async-branded destination.
- (decision) AD-10 projection derives from the plan only. Binds CAP-5. Prevents the projector and codegen disagreeing about which source columns a field needs. Rule: the projector walks MappingPlan nodes and unions their declared deps; it never inspects the destination class or adapter metadata; core emits neutral FieldSelection and only adapters translate to native shapes.
- (decision) AD-11 toolchain split and the no-plugin guarantee. Binds all packages. Prevents shipping artifacts that consumers cannot build, and prevents anyone reintroducing a transformer-plugin dependency. Rule: emit with TypeScript 6.x (compiler API required for .d.ts and for consumers' nest build); CI must additionally type-check the published .d.ts under TypeScript 7.x; the library must never require a ts transformer plugin of its consumers.
