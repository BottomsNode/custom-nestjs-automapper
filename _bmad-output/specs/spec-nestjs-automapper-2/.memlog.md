- (note) Sources: _bmad-output/brainstorming/brainstorm-automapper-differentiation-2026-09-08/brainstorm-intent.md (approved MoSCoW scope) and docs/DESIGN.md (earlier draft). Input is rich; distilled directly, no elicitation.
- (decision) RECONCILIATION with docs/DESIGN.md - it is superseded in five places and is absorbed as a source, not adopted as a companion. Superseded: (1) visible() strictness moves from runtime check to type-level T|undefined widening; (2) async mismatch moves from runtime throw at createMap to compile error via async-branded DTO; (3) the mapper-lifetime result cache section is void, replaced by a per-operation identity map; (4) the DTO-side descriptor gap is answered by Pick() for the common case, class-validator adapter for the rest; (5) schemaOf(Dto) OpenAPI generation is new MUST scope not present in DESIGN.md.
- (decision) CARRIED FORWARD from docs/DESIGN.md unchanged: SchemaAdapter interface as the metadata source; runtime codegen via new Function, one specialized fn per type pair; Nx monorepo under npm scope @nestjs-automapper/*; split map/mapAsync API; explicit ctx param in core with AsyncLocalStorage in the nestjs package; explicitly declared resolver deps; object-literal config keyed by destination field; 2.0 adapter surface limited to TypeORM.
- (constraint) core package stays zero-dependency. It computes a neutral FieldSelection tree; ORM-native select/include shapes are produced only by adapter packages. Rules out any direct ORM import in core.
- (constraint) Strict by default: an unresolved destination field is an error, and it surfaces at application boot, never per request. Rules out lazy first-call validation as the only check.
- (constraint) Resolver source dependencies are declared explicitly as typed path values, not inferred. Rules out proxy tracing and fn.toString() parsing, both of which under-collect on branches and break under minification.
- (constraint) Prefer a compile error over a runtime throw wherever the type system can carry the rule. Rules out runtime-only enforcement for visible() on required fields and for sync-mapping an async DTO.
- (constraint) Validation is direction-asymmetric and belongs on the write path only. Rules out running value validation on entities read from the project's own database.
- (constraint) Cache lifetime is scoped to exactly one map operation. Rules out any mapper-lifetime or cross-request result cache.
- (constraint) Reverse mapping derives DB-owned versus user-supplied fields from schema descriptors only. Rules out heuristics, naming conventions, or guessing.
- (capability) CAP-1 define a DTO without restating the entity's shape - no per-property decorators, no build-time transformer plugin, and the DTO still has a real runtime descriptor
- (capability) CAP-2 declare a derived field exactly once - one declaration yields both its static type and its runtime resolution
- (capability) CAP-3 learn a mapping is broken at application boot rather than in production
- (capability) CAP-4 diagnose a mapping failure from the error text alone, without opening the library source
- (capability) CAP-5 fetch only the columns and relations the DTO actually consumes
- (capability) CAP-6 map nested relations without registering each nested type pair by hand
- (capability) CAP-7 map an object graph containing cycles and repeated references safely, mapping each distinct source once
- (capability) CAP-8 derive a write-side DTO from a read-side one, with database-owned scalar fields dropped automatically
- (capability) CAP-9 produce an accurate OpenAPI schema for a DTO whose fields have no syntactic declaration site
- (capability) CAP-10 catch a mistyped resolver dependency path at compile time
- (decision) Non-goals for 2.0: mapper.query() DTO-to-query compiler (deferred to 3.0 - turns a mapper into a query builder); a bespoke per-property validation system (consume class-validator instead); any mapper-lifetime result cache; Prisma/Mongoose/Drizzle adapters (2.1+); browser or CSP-restricted runtimes (new Function targets Node).
- (decision) Companions: api-surface.md (draft public API - HOW detail kept out of the kernel per Spec Law 2); scope-tiers.md (full MoSCoW with SHOULD/COULD/WON'T and rationale); automapper-gap-analysis.md (root-cause analysis and the read/write asymmetry table that justifies CAP-8); architecture-diagrams.md (the descriptor-to-plan-to-emitters spine; diagrams always live in a companion).
- (assumption) Assumed the 2.0 target runtime is Node only, since new Function codegen was chosen and no browser requirement appears in any source.
- (assumption) Assumed schemaOf must reach parity with hand-written @ApiProperty; partial parity was judged worse than none because teams would then maintain both paths.
- (question) Nx package manager is unresolved - npm, yarn, or pnpm. Repo currently carries yarn.lock. pnpm's strict resolution is what would actually enforce the core zero-dependency constraint.
- (question) Default cycle policy is unresolved: throw, null, ref, or prune. prune conflicts with strict mode when the back-reference field is non-optional.
- (question) Behaviour of projectionFor when the plan contains context-gated fields but no ctx is supplied: throw, or project the union of all contexts. Throwing matches the strictness stance; union risks the over-fetching the feature exists to prevent.
- (question) Does extend() survive Nest DI, Swagger, and TS consumers via export-const-plus-export-type declaration merging? Unverified, and CAP-1, CAP-2 and CAP-9 all depend on it.
- (question) extend() has no path for a DTO mapped from two different sources; profiles survive only for that case. Is that acceptable for 2.0?

- (decision) OPEN QUESTION 4 RESOLVED by spike, not by argument. The Pick()/extend() + export-const-plus-export-type technique works. Confirmed: result is a function with a prototype (Nest DI token requirement), instanceof holds, the prototype chain survives extend(), the runtime field registry equals picked-plus-computed keys, resolvers and their declared deps are reachable at runtime, and instances carry REAL own-properties - which is precisely the v1 defect where 'key in dest' was always false. CAP-1, CAP-2, CAP-9 and CAP-10 are all cleared to build.
- (decision) OPEN QUESTION 1 RESOLVED: package manager is pnpm. Its strict node_modules is the only one of the three that actually enforces the core zero-dependency constraint and stops an adapter relying on a hoisted package it never declared. Migration cost is nil - the repo has no node_modules installed, so yarn.lock is simply removed.
- (decision) OPEN QUESTION 2 RESOLVED: cycles are detected statically in the plan graph at boot, consistent with strict-by-default. If a back-edge field is non-optional the boot fails naming the cycle path. If optional, the runtime default is prune (omit the back-edge). maxDepth 25 is a runtime backstop, and 'ref' emitting a reference marker is opt-in per map for graph-serialisation cases. Rejected 'throw' as default because legitimate diamond sharing must not be mistaken for a cycle - detection tracks the ancestor chain, not a global visited set.
- (decision) OPEN QUESTION 3 RESOLVED: projectionFor throws when the plan contains context-gated fields and no context is supplied. Projecting the union would silently over-fetch, which is the exact failure CAP-5 exists to prevent, and a silent over-fetch is undetectable in review. Consistent with the rest of the strictness stance.
- (decision) OPEN QUESTION 5 RESOLVED: the multi-source limitation is accepted for 2.0. A DTO mapped from two sources uses explicit profile registration via AutomapperModule.forFeature instead of the single-declaration form. Documented as a known boundary, not a defect. Item 13 (class-validator adapter, SHOULD) partially mitigates it by supplying descriptors for DTOs not derived from an entity.
- (decision) OPEN QUESTION 6 RESOLVED: docs/DESIGN.md is retained (it is cited in sources: for audit) but gets a superseded banner pointing at this SPEC, so no implementer builds from its five stale decisions. Not deleted, because deleting a file listed in frontmatter breaks traceability.
- (event) spec re-derived after resolving all six open questions; zero open questions remain; docs/DESIGN.md banner-marked superseded
- (decision) IMPLEMENTATION CORRECTION to api-surface.md. The documented DTO form (export const X = extend(...) + export type X = InstanceType<typeof X>) is WRONG and is now forbidden. The self-referential alias makes TypeScript break the cycle by falling back to the key parameter's constraint, so the DTO silently regains every field of the source including password. Supported form is a class declaration extending the expression, matching Nest's PickType idiom. Descriptor block also synced to the implemented AD-14 shape (required provenance flags) and AD-10 FieldSelection vocabulary.
